## Learned User Preferences

- Do not modify `models.py` or `grid_data_prep.py`; wrap them with new service code instead.
- Keep superseded circuit-level modules (`data_prep.py`, `main.py`, `prep_hrrr.py`) for reference only; do not build new work on them.
- Treat sibling `dataset_demo/` as read-only reference; never modify or commit there: new code goes only in Wildfire Services.
- Prefer a reviewable plan before applying structural or service changes; use separate commits for baseline, restructure, and new service code.
- Verify data by content (e.g. NetCDF time coordinates), not filenames; this project has a history of filename-vs-content mismatches.
- Prefer failing verification loudly over adjusting tests or expectations to pass; ground-truth against source files or SQL. For visual work, verify against the rendered result (screenshots), not programmatic element/property checks; if rendering cannot be inspected, mark unverified rather than reporting it done. Distinguish live Ask verification from canvas-API render-then-screenshot checks.
- If fitted risk params are missing, fail with a clear message rather than auto-fitting; pause for human verification of adjacency rebuild stats (nnz / average neighbors) before running model fits.
- When fitted coefficients look scientifically implausible, audit covariates before refitting.
- Prefer dropping corrupt weather days over substituting a different hour-of-day HRRR export when that would introduce a systematic temperature offset.
- Do not overclaim small OOS log-likelihood gaps; quantify uncertainty (e.g. day-blocked bootstrap) and treat noise-scale ΔLL as a tie.
- Document durable scientific findings and data caveats in the README.
- After each Historical Map canvas slice, confirm the Planning Tool tab still renders plot images before calling the slice done. Serve with `python frontend/serve.py` (not `python -m http.server` from `frontend/`); canvas CSS/JS stays scoped to `#sfps-tab-historical` / `#historical-canvas-host`. Planning Tool is out of scope for canvas work. StatCard is a 1–3 card strip (do not stretch a single card across the canvas); SpatialContext lays Coordinates, IOU, HFTD, county, and grid cell horizontally; Comparison, TimeSeries, and RecordTable stay full width; the map fills the canvas and the Leaflet instance stays alive when collapsed; idle map filters grey when a non-map answer is showing. Working reference: [`frontend/CANVAS.md`](frontend/CANVAS.md).

## Learned Workspace Facts

- Repo is Wildfire Services (personal `origin`: `ByteMasterMike/Wildfire-Services`; team repo is `Woody-Zhu-Group/Wildfire-Platform` on the `platform` remote, and pushes go to `platform`) with `services/{risk_forecasting,data_query,visualization,comparison,agent,gpu_control,shared}/`, `website/` (the current React/TypeScript workspace, built into `docs/`), `frontend/` (the older local Historical Map and Planning Tool), `shared/`, `db/`, `deploy/`, and `tests/`; risk service wraps the grid cNHPP ignition model. On Windows, run modules with repo-root `PYTHONPATH` and `PYTHONIOENCODING=utf-8` so `models.py` console output does not crash on ξ characters.
- PostGIS warehouse: `db/schema.sql` + `python -m db.loaders` (Docker Compose PostGIS 16 on host port **5433**). DB settings in `shared/db.py` (loads repo `.env`). Source map data is read-only from sibling `dataset_demo/assets/data`, except HFTD tier and IOU territory polygons, which load from cached CPUC FeatureServer Esri JSON in `data/boundaries/` behind a validity and area gate (PR #45, `docs/DATA_CHANGE_HFTD_IOU.md`). Circuit IDs are TEXT 9-digit zero-padded, never numeric. No FKs from EPSS/PSPS to circuits; orphans reported at load + validation (17 PSPS circuit IDs lack GNA geometry). No CPZ polygons in dataset_demo (known gap; HFTD Tier 2/3 only). CPUC ignitions get a `county` column at load via point-in-polygon against Census TIGER California county polygons (`wildfire.counties`); `/spatial/point` returns that county.
- Data query API: `uvicorn services.data_query.app:app --reload --app-dir .`, CAL FIRE defaults to `incident_type in (Wildfire, Fire)` excluding nulls; use `incident_type=untyped` / `utility=untagged`. Leading-zero circuit test ID: `043371102` (inventory example `012041102` is absent). Verification: `python tests/report_results.py` (requires data_query :8000 and risk :8001); EPSS loader drops 1 exact duplicate in 2024 (raw CSV 2788 → loaded 2787).
- Visualization API: `uvicorn services.visualization.app:app --port 8002 --app-dir .`, EPSS map-layer returns circuit lines (`include_outages=true` embeds outage rows); `/event-detail` for `circuits` returns `outages`, for `psps` returns `affected_circuits`. CORS enabled. Ignitions: attribute `utility=` ≠ spatial `/spatial/summary` (PGE 2024: 532 vs 536). Frontend is a slim copy without `website_plots`; Historical Map uses visualization `:8002`, HDWI stays static, and CAL FIRE uses the verified Wildfire/Fire default and stays red `#b91c1c` (one hue per dataset; magnitude via size or opacity). Local UI: `python frontend/serve.py` on **8765** (mounts sibling `dataset_demo` at `/dataset_demo/`); plain `http.server` from `frontend/` 404s Planning Tool plots.

- Agent prototype: `uvicorn services.agent.app:app --port 8004 --app-dir .`, deterministic routing precedes seven grouped OpenAI-compatible tools (`data_query_records`, `data_query_rank`, `data_query_spatial`, `visualization_create`, `visualization_inspect`, `risk_forecast`, `comparison_run`); `risk_surface` is router-only. Production runs `qwen2.5:7b` (default in `services/agent/config.py`, overridable via `AGENT_MODEL`). The Jev decision layer (TypeSafe, a non-generative typed-decision model with probabilities; see CLAUDE.md) lives under `services/agent/decisions/` (`jev_policy.py`, `backend.py`, `v3.py`). `AGENT_JEV_MODE` accepts `off` (default), `shadow`, `tool_pick`, `tool_pick_template`, and `decide` (router backstops first, then Jev's disposition behind a 0.8 decline gate and a 0.9 answer gate; `docs/JEV_DECIDE.md`); plan mode is open PR #46. `AGENT_JEV_BACKEND` is `typesafe` (default) or `openrouter`, and `AGENT_LLM_PROVIDER=openrouter` (off by default) moves the model tier to OpenRouter (see `docs/OPENROUTER.md`). Location phrasing (`where` / `see where` / `locations of`) routes to a map, even when the question also sounds like a count. Year-scoped geographic counts keep the Map on the canvas (same filters, no extra tool); partial-year counts, risk, and spatial summaries stay map-less. Caveats attach after any successful tool path (path-independent). Every utility ignition count gets a same-period attribute/spatial companion comparison. Relative dates resolve in the harness against the current date (never the model); a deterministic rule must not fire if the question has filters the rule cannot express. Frontend Ask panel uses SSE `POST /ask/stream`; leave `POST /ask` unchanged for eval. Do not add a `render_view` tool (canvas views are harness-planned). The eval runner defaults to qwen3:4b; always pass --models qwen2.5:7b --thinking off --modes constrained to match production. Eval files on main: cases.json (107), jev_paraphrases.json (41), and holdout v1 (`jev_holdout.json`, 97 rows, 63 without `needs_human_review`); holdouts v2 and v3 arrive with PR #46. Ollama lacks `tool_choice`; track no-tool/direct-answer attempts (the OpenRouter path sends `tool_choice: "required"`).
- Fitted params live at `services/risk_forecasting/artifacts/cnhpp_params.npz` (committed in `6b58596`, ~2KB); risk API runs on :8001. California grid has 824 cells at 0.24° spacing; rebuilt adjacency should have nnz ≈ 3922 and ~3.8 average neighbors.
- Covariate order is TMP, SPFH, wind_speed, NDVI, fm100, plus an intercept; single-date prediction needs a trailing covariate window because of the spatial memory term. Do not call `grid_data_prep.load_year()` (broken signature); fit/predict wrappers call the year loaders directly and concatenate per-year `events_YYYY.csv` files.
- Dec 2–31 2020 weather was corrupt in `California_HRRR_daily_2020_01.csv` (TMP held SPFH-scale values); those 30 days are dropped, and `prep_hrrr_grid.py` rejects days whose median TMP is outside 200–330 K.
- Grid cell 461 has all-NaN NDVI/fm100 across vegetation NetCDFs; cells 71, 439, and 521 are all-NaN for fm100 only (mean-filled in wrappers).
- Positive SPFH coefficient is a covariate-semantics issue (SPFH is not dryness; eventual fix is VPD or RH); fm100 is largely redundant with TMP (train correlation ≈ −0.64). On the corrected 824-cell weather grid, cNHPP vs NHPP OOS ΔLL is a statistical tie (sign flips across years; CIs cover 0).
