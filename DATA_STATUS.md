### CPUC fire events (events_YYYY.csv, per-year combined PG&E+SCE+SDG&E)
Columns (unnamed index, Lat, Lon, T):
    ,Lat,Lon,T
    0,37.72173,-122.38793,2020-12-27 09:18:00

T is a pandas-parseable datetime string. Lat/Lon are decimal degrees, sometimes with more
precision on some rows than others (e.g. 38.1522374463 vs 37.95526) -- this is a real
inconsistency observed in the source data, not a transcription error.
Approximate row counts observed previously: 2020=688, 2021=675, 2022=613, 2023=480, 2024=741.
These counts are from memory of prior output logs; re-verify on re-upload.

### grid_weather_YYYY.csv (prep_hrrr_grid.py output)
Columns: date, cell_id, lat, lon, TMP, SPFH, wind_speed
    date,cell_id,lat,lon,TMP,SPFH,wind_speed
    2020-01-01,0,40.27414872734404,-124.3495909345701,284.6126937866211,0.0075975,3.576366508235474
TMP is in Kelvin (raw HRRR units, never converted to Celsius in the pipeline -- worth fixing
or at least noting in any writeup). SPFH is specific humidity (kg/kg). wind_speed is computed
as sqrt(U^2 + V^2) from the two HRRR wind-component columns inside prep_hrrr_grid.py; the U/V
components themselves are not retained in the output. One row per (date, cell_id): 824 cells x
365 or 366 days per year.

### daily_gridded_CA_YYYY.nc (vegetation, Marco's / lab data -- NOT generated by this pipeline)
NetCDF with dimensions (time: 365 or 366, cell: 824) and variables NDVI, EVI, fm100, fm1000,
elevation, plus 1-D cell, lat, lon coordinate arrays. fm100 = 100-hour fuel moisture (percent).
grid_data_prep.py:load_vegetation_for_year() assumes this exact structure and aligns on the
`cell` coordinate, not on array position -- if the re-uploaded file has cells in a different
order, that alignment step is what matters, not an assumption that order is preserved.

### GNA circuit topology (superseded circuit-level model only, not used in the final grid model)
gna_circuits.dbf attribute table included at minimum: circuitid, substation (used to build
adjacency: circuits sharing a substation ID are treated as neighbors), division. The .shp held
line geometry (Web Mercator, EPSG:3857) used only for the spatial risk map visualization and
for computing circuit midpoints, not for the adjacency itself.

## HOW TO REBUILD data/grid_W.pkl (the grid adjacency matrix)
This is fully deterministic from grid_cells.csv alone, no external data needed. Logic (already
implemented, just needs to be re-run):
1. Snap each of the 824 cells to integer (row, col) grid indices using 0.24-degree spacing.
2. Connect each cell to its N/S/E/W neighbors that exist in the grid, plus a self-loop.
3. Equal weights per cell, normalized so each row of W sums to 1.0.
Expected result when re-run: 3,922 nonzero entries, average 3.8 real neighbors per cell (some
edge/coastal cells have fewer). This was verified in the prior session; use it as a sanity check
after rebuilding.
